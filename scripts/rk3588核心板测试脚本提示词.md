# 使用说明

复制下面「提示词」整段发给大模型。只改【板卡名称】，并按同样一句一条追加测试项目。把返回的 `.sh` 保存后，在 BoardTestTool 里打开即可。

## 提示词

你是嵌入式 Linux 板卡生产测试脚本工程师。请为板卡【rk3588核心板】生成一份**跨系统可执行**、并被 BoardTestTool 解析的生产测试 sh 脚本。

待测板可能是 Buildroot / Ubuntu / Debian，也可能是 BusyBox ash。**不要写死发行版，用户不会告诉你发行版。** BoardTestTool 把脚本 SFTP 到 `/tmp/boardtest_xxx.sh` 后用 **`sh` 执行**（可能是 dash / ash / bash-as-sh），stdout 解析 JSON。生成的脚本必须在这些 `sh` 上都能跑完并打出合法 JSON。

硬约束（必须遵守）：

1. **解释器**：第一行 `#!/bin/sh`。按 POSIX `sh` 写，须能被 dash（Debian/Ubuntu 的 `/bin/sh`）、ash（BusyBox/Buildroot）、bash-as-sh 执行。
2. **禁止 bashism**：`function`、`local`、数组、`[[ ]]`、`source`、`$'...'`、进程替换、把 `echo -e` 当依赖。
3. **禁止未定义命令**：先定义再调用。辅助函数名只能是 `log`（写 stderr）、`json_escape`、`record_result`。禁止自创 `loge`/`record`/`log_err` 等。必须先原样带上下面骨架，再写测试逻辑。
4. **命令可移植**：只用各系统一般都有的：`sh` 内置、`test`/`[`、`printf`、`cat`、`dd`、`stty`、`ls`、`id`，以及骨架里的 `sed`/`awk`。`timeout`、`ip`、`ping` 等可能缺失时必须先 `command -v` 探测；没有则该项 `fail`，`msg` 写清「命令不存在: xxx」，禁止因 command not found 中断整脚本。
5. **不要写死 BusyBox 或 Ubuntu**：禁止 `busybox xxx`；禁止依赖 GNU 长选项（如 `dd status=progress`、`timeout --foreground`）。`stty`/`dd` 只用短选项。
6. **协议**：stdout 只出一段 JSON 数组（最后 `printf '[%s]\n' "$ITEMS_JSON"`）；日志全走 `log`（stderr）。字段仅 `test_name`/`test_item`/`result`/`msg`/`raw_log`；`result` 仅 `pass`/`fail`。单项失败继续，禁止 `set -e` / 单项 `exit 1`，最后 `exit 0`。样例：
   `[{"test_name":"ttyUSB0自发自收测试","test_item":"ttyusb0_loopback","result":"pass","msg":"收发一致","raw_log":"发送: ABC | 接收: ABC"},{"test_name":"ttyUSB1自发自收测试","test_item":"ttyusb1_loopback","result":"fail","msg":"设备不存在: /dev/ttyUSB1","raw_log":"无此节点"}]`
7. **串口自发自收**：设备 `/dev/对应节点`；`exec N<>` 打开后 `stty` 配 115200 8N1 raw 无流控关回显（短选项，如 `stty 115200 cs8 -cstopb -parenb -crtscts -ixon -ixoff raw -echo`）；`printf` 写固定数据，探测到 `timeout` 后再用 `timeout` + `dd bs=1 count=N` 读回比对。设备不存在、权限不足、打不开、stty 失败、timeout 不存在、超时未收满、数据不一致，分别 `record_result` 记 `fail` 并在 `msg` 写清原因，然后 `return 0` 继续下一项。
8. 只输出一份完整 `.sh`，不要 markdown 围栏，不要脚本前后的解释。第一个字符必须是 `#`，最后是 `exit 0`。

必须先原样包含下面三函数（可改注释，不可改函数名、不可省略）：

```
log() { echo "$@" >&2; }

json_escape() {
    sed -e 's/\\/\\\\/g' -e 's/"/\\"/g' | \
        awk 'BEGIN{ORS=""} { if(NR>1) printf "\\n"; printf "%s", $0 }'
}

ITEMS_JSON=""
record_result() {
    _esc_name="$(printf '%s' "$1" | json_escape)"
    _esc_item="$(printf '%s' "$2" | json_escape)"
    _esc_result="$3"
    _esc_msg="$(printf '%s' "$4" | json_escape)"
    _esc_raw="$(printf '%s' "$5" | json_escape)"
    _obj="$(printf '{"test_name":"%s","test_item":"%s","result":"%s","msg":"%s","raw_log":"%s"}' \
        "$_esc_name" "$_esc_item" "$_esc_result" "$_esc_msg" "$_esc_raw")"
    if [ -z "$ITEMS_JSON" ]; then
        ITEMS_JSON="$_obj"
    else
        ITEMS_JSON="$ITEMS_JSON,$_obj"
    fi
}
```

测试项目：

1、ttyUSB0自发自收测试，对于串口硬件的rxd和txd会短接环路。
2、ttyUSB1自发自收测试，对于串口硬件的rxd和txd会短接环路。
3、/dev/spidev1.0读写测试，可以向0地址写入0x56,然会回读看看是否正确。
